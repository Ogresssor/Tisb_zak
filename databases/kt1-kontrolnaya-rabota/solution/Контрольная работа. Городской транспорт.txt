Контрольная работа по дисциплине «Базы данных»
Тема: Проектирование базы данных «Городской транспорт»

1. Этап проектирования

База данных «Городской транспорт» предназначена для хранения информации о маршрутах общественного транспорта города. Она позволяет узнать вид транспорта, номер маршрута и остановки, через которые он проходит.

В базе данных необходимо хранить сведения об автобусах, троллейбусах, трамваях и метро. Для каждого маршрута указываются его номер, название и вид транспорта. Остановки записываются в порядке следования. Прямое и обратное направления могут отличаться.

2. Инфологическая модель

Выделены следующие сущности.

Вид транспорта:
Код вида транспорта, название вида транспорта.

Маршрут:
Код маршрута, номер маршрута, название маршрута, код вида транспорта.

Остановка:
Код остановки, название остановки.

Остановка маршрута:
Код маршрута, направление движения, порядковый номер остановки, код остановки.

Связи между сущностями:

1. Один вид транспорта может иметь несколько маршрутов. Каждый маршрут относится к одному виду транспорта. Связь один ко многим.
2. Один маршрут содержит несколько остановок. Одна остановка может встречаться на нескольких маршрутах. Связь многие ко многим.
3. Для указания порядка остановок и направления движения используется сущность «Остановка маршрута». Она связывает маршруты с остановками.

3. Реляционная схема базы данных

Таблица «Виды_транспорта»:
id_вида: целое число, первичный ключ.
название: текст, название вида транспорта.

Таблица «Маршруты»:
id_маршрута: целое число, первичный ключ.
номер: текст, номер маршрута.
название: текст, название маршрута.
id_вида: целое число, внешний ключ на Виды_транспорта.id_вида.

Таблица «Остановки»:
id_остановки: целое число, первичный ключ.
название: текст, название остановки.

Таблица «Остановки_маршрутов»:
id_маршрута: целое число, внешний ключ на Маршруты.id_маршрута.
направление: текст, прямое или обратное.
порядок: целое число, порядковый номер остановки.
id_остановки: целое число, внешний ключ на Остановки.id_остановки.

В таблице «Остановки_маршрутов» составной первичный ключ образован полями id_маршрута, направление и порядок. Это позволяет отдельно записать последовательность остановок для каждого направления.

Связи между таблицами по конкретным полям:

Виды_транспорта.id_вида связано с Маршруты.id_вида.
Маршруты.id_маршрута связано с Остановки_маршрутов.id_маршрута.
Остановки.id_остановки связано с Остановки_маршрутов.id_остановки.

4. Пример заполнения базы данных

Таблица «Виды_транспорта»:
1; Автобус
2; Трамвай
3; Троллейбус
4; Метро

Таблица «Маршруты»:
1; 12; Вокзал, Парк; 1
2; 3; Площадь, Университет; 2

Таблица «Остановки»:
1; Вокзал
2; Площадь
3; Парк
4; Университет

Таблица «Остановки_маршрутов»:
1; прямое; 1; 1
1; прямое; 2; 2
1; прямое; 3; 3
1; обратное; 1; 3
1; обратное; 2; 2
1; обратное; 3; 1
2; прямое; 1; 2
2; прямое; 2; 4
2; обратное; 1; 4
2; обратное; 2; 2

В таблице «Маршруты» поля перечислены в таком порядке: id_маршрута, номер, название, id_вида. В таблице «Остановки_маршрутов» указаны id_маршрута, направление, порядок и id_остановки. Для других видов транспорта сведения могут добавляться аналогичным образом.

5. Вывод

В ходе контрольной работы была спроектирована база данных «Городской транспорт». Выделены основные сущности, определены связи между ними и составлена схема из четырех таблиц. Такая структура позволяет хранить маршруты разных видов общественного транспорта и порядок их остановок в обоих направлениях.
